# Rjay Solamo · Developer portfolio

A portfolio for Rjay Solamo, Web3 Engineer / Blockchain Builder. Application logic uses Rust: Leptos 0.8 server-side rendering and WebAssembly hydration, Axum, Tokio, and Serde. HTML and a custom local CSS stylesheet provide presentation. The existing architecture is retained from the official [leptos-rs/start-axum](https://github.com/leptos-rs/start-axum) starter. No CSS framework, database, API credentials, handwritten JavaScript, or Node toolchain is needed. The browser loader JavaScript is generated by Leptos.

## Local setup

Install Rust using [rustup](https://rustup.rs), then from this directory:

```bash
rustup toolchain install 1.99.1 --profile minimal --component rustfmt,clippy --target wasm32-unknown-unknown
cargo install cargo-leptos --version 0.3.11 --locked
cargo leptos watch
```

Open http://localhost:3000. The server listens on `0.0.0.0:3000`; hot reload uses port 3001. Linux needs a C linker (Ubuntu: `sudo apt-get install build-essential pkg-config`). First builds download crates and cargo-leptos build helpers and take several minutes. Keep `Cargo.lock` for reproducible dependencies. System sans-serif and monospace fonts avoid remote font requests. No provider APIs are called.

Do not enable `ssr` and `hydrate` together: they are separate server and browser compilation targets, so Clippy uses separate feature/target invocations rather than `--all-features`. There is one Cargo package, not a multi-package workspace. No unit tests currently exist; the Cargo test commands verify the test and documentation build targets. Check desktop and narrow mobile layouts, keyboard focus, mobile menu open/close/Escape, all section links, project links, architecture and community disclosures, and `/missing` returning a 404. There are no form inputs or server-side user mutations in this version.

## Production Linux deployment

Build on a Linux machine compatible with your server architecture and libc:

```bash
cargo leptos build --release --cargo-locked
mkdir -p deploy/target
cp target/release/rjay-portfolio deploy/
cp -R target/site deploy/target/site
cd deploy
LEPTOS_SITE_ADDR=127.0.0.1:3000 \
LEPTOS_SITE_ROOT=target/site \
LEPTOS_ENV=PROD \
SITE_ORIGIN=https://portfolio.your-domain.com \
./rjay-portfolio
```

Replace the example hostname with your domain. Run from the deployment directory, keeping the generated `target/site/pkg` files together with the binary. Axum serves those CSS, WASM, generated JS, and public assets. Do not serve `src`, `.git`, or configuration secrets. No environment variables contain secrets in this version. `.env` files are ignored, and this application does not automatically load them.

Run the binary under systemd (set `WorkingDirectory`, the four environment values above, `ExecStart`, an unprivileged user, and `Restart=on-failure`). Expose only the reverse proxy, not the Rust server port. Example Caddy configuration with automatic HTTPS:

```caddyfile
portfolio.your-domain.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:3000
}
```

Point DNS at your server, open ports 80 and 443, and let Caddy provision TLS. Verify the public homepage, `/robots.txt`, `/sitemap.xml`, unknown-route 404, asset loading, and mobile menu hydration after deployment. Use conservative caching for HTML; rebuild and deploy the binary and assets together. The default build does not fingerprint asset names, so do not apply immutable caching across releases.

This build starts a persistent Rust server. Container hosts or a Linux VPS can run it with suitable build and runtime configuration. Vercel's Rust Functions runtime requires a separate adapter and routing/build configuration; this repository has not been adapted or verified there. Static-only hosting cannot run the current SSR binary. No public deployment has been performed by this task. HTTPS and DNS require your actual server and domain.

# Rjay Solamo · Developer portfolio

A Rust-only full-stack portfolio using Leptos 0.8 SSR and hydration, Axum, Tokio, Serde, CSS, and static Rust content. Scaffolded from the official [leptos-rs/start-axum](https://github.com/leptos-rs/start-axum) template. No database, API credentials, handwritten JavaScript, or Node toolchain is needed. The WebAssembly loader JavaScript is generated by Leptos.

## Local setup

Install Rust using [rustup](https://rustup.rs), then from this directory:

```bash
rustup toolchain install 1.99.1 --profile minimal --component rustfmt,clippy --target wasm32-unknown-unknown
cargo install cargo-leptos --version 0.3.11 --locked
cargo leptos watch
```

Open http://localhost:3000. The server listens on `0.0.0.0:3000`; hot reload uses port 3001. Linux needs a C linker (Ubuntu: `sudo apt-get install build-essential pkg-config`). First builds download crates and cargo-leptos build helpers and take several minutes. Commit `Cargo.lock` for reproducible dependencies. Google Fonts supplies DM Sans and IBM Plex Mono; system fonts are fallbacks when offline. No provider APIs are called.

## Checks

```bash
cargo fmt --check
cargo check --locked --features ssr
cargo check --locked --lib --target wasm32-unknown-unknown --features hydrate
cargo clippy --locked --features ssr -- -D warnings
cargo clippy --locked --lib --target wasm32-unknown-unknown --features hydrate -- -D warnings
cargo leptos build --release --cargo-locked
```

Do not enable `ssr` and `hydrate` together: they are separate server and browser compilation targets. Check desktop and narrow mobile layouts, keyboard focus, mobile menu open/close, section links, project links, and `/missing` returning a 404. There are no form inputs or server-side user mutations in this version.

## Editing content and publication checklist

- `src/content.rs`: static project, skill, development history, and community data. Project cards support optional repository and demo URLs. Serde serialization is available for this content model.
- `src/app.rs`: Rust UI, mobile menu state, routing, SEO, and 404 page.
- `style/main.css`: responsive layout, diagrams, keyboard focus and reduced motion.
- GitHub profile and the InDexAI, uwifin, and airchainpay repository URLs were verified against GitHub's public repository listing during implementation (2026-10-22). Their README files were consulted; descriptions deliberately distinguish direction from shipped functionality. Technology lists describe those projects, not this portfolio's implementation.
- All work-history dates and roles and all community affiliations are **awaiting owner confirmation**. The visible notice is intentional. Confirm them before public launch; do not silently treat community participation as employment.
- CLI/infrastructure tools remain an area of interest until specific repositories and contributions can be verified. No performance, deployment, user-count, or seniority claims are made.
- Writing entries are **planned topics**, not published articles. Add article routes and unique metadata only when articles exist.
- Only GitHub contact information is supplied. Add email, LinkedIn and X only after confirmation. There is no fake contact form.
- Set `SITE_ORIGIN` to the real public origin before launch. Sitemap and robots routes use this validated origin, defaulting to `http://localhost:3000` locally.

## Production Linux deployment

Build on a Linux machine compatible with your server architecture and libc:

```bash
cargo leptos build --release --cargo-locked
mkdir -p deploy/target
cp target/release/rjay-portfolio deploy/
cp -R target/site deploy/target/site
cd deploy
LEPTOS_SITE_ADDR=127.0.0.1:3000 \
LEPTOS_SITE_ROOT=target/site \
LEPTOS_ENV=PROD \
SITE_ORIGIN=https://portfolio.your-domain.com \
./rjay-portfolio
```

Replace the example hostname with your domain. Run from the deployment directory, keeping the generated `target/site/pkg` files together with the binary. Axum serves those CSS, WASM, generated JS, and public assets. Do not serve `src`, `.git`, or configuration secrets. No environment variables contain secrets in this version. `.env` files are ignored, and this application does not automatically load them.

Run the binary under systemd (set `WorkingDirectory`, the four environment values above, `ExecStart`, an unprivileged user, and `Restart=on-failure`). Expose only the reverse proxy, not the Rust server port. Example Caddy configuration with automatic HTTPS:

```caddyfile
portfolio.your-domain.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:3000
}
```

Point DNS at your server, open ports 80 and 443, and let Caddy provision TLS. Verify the public homepage, `/robots.txt`, `/sitemap.xml`, unknown-route 404, asset loading, and mobile menu hydration after deployment. Use conservative caching for HTML; rebuild and deploy the binary and assets together. The default build does not fingerprint asset names, so do not apply immutable caching across releases.

This application requires a persistent Rust server; static-only hosts and JavaScript-only serverless platforms cannot run this SSR binary directly. No public deployment has been performed by this task. HTTPS and DNS require your actual server and domain.
